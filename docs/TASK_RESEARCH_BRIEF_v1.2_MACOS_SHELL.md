# TASK_RESEARCH_BRIEF_v1.2_MACOS_SHELL

## Исходные данные и цель
- Цель: создание нативного macOS-приложения (.app) "Речь в текст" с использованием существующего веб-интерфейса и Python-бэкенда (v1.1).
- Критерии приемки: отдельное окно с веб-интерфейсом, собственный сервер на свободном 127.0.0.1 порту, ожидание готовности (русские состояния, кнопка повтора), повторное открытие по клику в Dock, красная кнопка скрывает (но не закрывает) приложение, Cmd-Q завершает процесс корректно, безопасность (CSRF, пути), сборка .app.

## Варианты реализации

### Вариант 1: Swift AppKit + WKWebView (с встраиванием Python)
- Плюсы: Идеальная интеграция с macOS (события Dock, Cmd-Q, скрытие окна), минимальное потребление ресурсов UI, нативный WKWebView.
- Минусы: Сложность сборки (упаковка Python окружения внутрь Swift .app), необходимость написания Swift-моста для управления жизненным циклом сервера.

### Вариант 2: PyWebView + PyInstaller
- Плюсы: Единая кодовая база на Python, автоматически использует нативный WKWebView на macOS, легкость упаковки через PyInstaller, простота запуска локального сервера на динамическом порту.
- Минусы: Ограниченный контроль над специфичными событиями macOS (например, клик по иконке в Dock для восстановления скрытого окна), может потребовать использования pyobjc для тонкой настройки NSApplication.

### Вариант 3: Electron / Tauri
- Плюсы: Широкие возможности кастомизации окон, развитая экосистема.
- Минусы: Огромный размер бандла (Electron) или необходимость компиляции Rust (Tauri), избыточность для простого локального сервера, высокое потребление памяти. Не "нативный" WebView в случае Electron.

## Выбор и обоснование
Выбран **Вариант 2 (PyWebView + PyInstaller с интеграцией pyobjc)**.
Обоснование: PyWebView обеспечивает достаточную интеграцию с WKWebView, а использование PyInstaller позволяет собрать автономный .app без сложных зависимостей (в отличие от Swift). Специфичные требования (Dock, красная кнопка) будут решены либо встроенными средствами PyWebView (hide_window_on_close), либо инъекцией pyobjc.

## План действий
1. Интеграция PyWebView для отображения UI.
2. Механизм динамического выбора порта 127.0.0.1 и запуска Flask/FastAPI в отдельном потоке.
3. Добавление кастомного экрана загрузки (на русском) с polling сервера и кнопкой retry.
4. Настройка обработчиков macOS (красная кнопка -> hide, Dock -> unhide, Cmd-Q -> graceful shutdown с сохранением checkpoints).
5. Сборка с использованием PyInstaller в папку dist.
6. Написание E2E тестов жизненного цикла (single-instance, cleanup, readiness).

## Зависимости и риски
- Зависимости: pywebview, pyobjc (опционально), pyinstaller.
- Риски: управление процессами при Cmd-Q (избежание orphans), взаимодействие WebView с микрофоном (разрешения macOS).
