# Речь в текст (rech-v-tekst)

Локальный, безопасный и отказоустойчивый инструмент для записи встреч и вебинаров, извлечения звука из видео, распознавания речи и составления умных конспектов на **macOS**.

Все ключевые операции выполняются локально на вашем компьютере: звук и расшифровка не передаются во внешние сети без вашего прямого информированного согласия.

Полный путеводитель по интерфейсу, поведению кнопок, форматам экспорта и архитектурным гарантиям: **[Документация возможностей (FEATURES.md)](FEATURES.md)**.

---

## Быстрый старт

### Вариант 1. Запуск в один клик (Рекомендуется)
Дважды кликните на файл **`Start.command`** в Finder (или выполните `./Start.command` в терминале):
1. Скрипт проверит наличие Python 3 и готовность утилит.
2. Сервер запустится локально на `http://127.0.0.1:8787`.
3. Веб-интерфейс автоматически откроется в браузере.

### Вариант 2. Проверка окружения через терминал
```bash
# 1. Проверка доступности компонентов (безопасный dry-run аудит)
./setup.sh

# 2. Локальная установка компонентов распознавания (скачивание модели + сборка whisper.cpp)
./setup.sh --install

# 3. Запуск веб-интерфейса
python3 ui.py
# Откройте в браузере: http://127.0.0.1:8787
```

> [!TIP]
> Все компоненты также можно настроить и установить прямо в веб-интерфейсе: нажмите **«⚙️ Настройки»** в шапке страницы.

## Ключевые архитектурные свойства

1. **Сохранность звука (Архитектурное решение P0)**:
   - Захват звука выполняется в **нативной частоте дискретизации устройства** (определяется через `ffmpeg` avfoundation при зондировании устройства, обычно 44.1 кГц или 48 кГц) без ресемплирования на лету.
   - Автономно доказана корректность офлайн-нормализации синтетических потоков 44.1 кГц и 48 кГц в 16 кГц mono WAV без искажения длительности (с точностью до кадра/округления заголовка).
   - Непрерывный захват пишет в атомарные сегменты (`segment_time 120s`) с ведением журнала `journal.csv`.
   - Нормализация в 16 кГц mono WAV для Whisper выполняется отдельным независимым шагом с валидацией целостности заголовков RIFF/WAVE и совпадения длительности.
   - Пользовательские исходные медиафайлы **никогда не удаляются** и не модифицируются.
2. **Безопасность файловой системы и процессов**:
   - Приватные права доступа (`0o700` на папки, `0o600` на файлы).
   - Защита от symlink и hardlink атак (`O_NOFOLLOW`, проверка `st_nlink == 1`, запрет directory traversal).
   - Атомарная запись (`atomic_write_text`, `atomic_write_bytes`) через временные файлы с `os.replace`.
   - Надежные межпроцессные блокировки (`ProcessLock` через `fcntl.flock`).
3. **Безопасный локальный Web UI**:
   - Сервер слушает строго `127.0.0.1`.
   - Защита от DNS-rebinding (проверка заголовка `Host`).
   - Защита от CSRF и Cross-Origin атак (`Origin` validation + криптографический CSRF-токен для всех мутирующих запросов).
   - Защита от утечек данных через LLM: саммари требует явного подтверждения (opt-in checkbox). Провайдер Codex отключён из-за рисков доступа к файлам в read-only песочнице; Claude CLI вызывается с принудительным флагом `--tools ""`.
4. **Управление жизненным циклом и отказоустойчивость**:
   - Явные durable-состояния: `recording`, `ready`, `processing`, `completed`, `failed`, `interrupted`.
   - Автоматическая выверка сессий при старте сервера (`reconcile_on_startup`).
   - Корректное завершение дерева процессов с эскалацией сигналов (`SIGINT` → `SIGTERM` → `SIGKILL`).

## Требования

- **macOS** 13+ (Apple Silicon M-серии для полной поддержки распознавания и диаризации; Intel поддерживается в части базовой записи и Whisper).
- **Python** 3.9+.
- **ffmpeg** и **ffprobe** (`brew install ffmpeg` или локально в `work/task_local_ffmpeg`).
- **whisper.cpp** (`whisper-cli`) — собирается автоматически в 1 клик через «⚙️ Настройки» или скрипт `./setup.sh --install`.
- **Модель Whisper** (`ggml-large-v3-turbo.bin`, 1.51 ГБ) — загружается и проверяется по SHA-256 автоматически.
- **Компоненты диаризации речи (v1.1)**:
  - `sherpa-onnx` (статический бинарный файл диаризации и runtime-библиотеки C-API / onnxruntime под arm64).
  - Модель сегментации речевой активности `pyannote-segmentation-3-0` (ONNX int8).
  - Модель извлечения 512-мерных эмбеддингов диктора `3dspeaker_speech_eres2net_base_sv_zh-cn_3dspeaker_16k` (ONNX 16k).
  - Устанавливаются и верифицируются автоматически в 1 клик через «⚙️ Настройки» или скрипт `./setup.sh --install`.
- **BlackHole 2ch** (опционально) — требуется **только** для захвата системного звука вебинаров/Zoom. Для записи с микрофона и импорта готовых файлов BlackHole не нужен.

## Настройка Multi-Output Device (для записи Zoom / системного звука)

macOS требует создания объединенного аудиовыхода, чтобы звук одновременно шел в ваши наушники и в виртуальный драйвер BlackHole:

1. Откройте **Audio MIDI Setup** (в Spotlight введите `Audio MIDI Setup`).
2. В левом нижнем углу нажмите **«+» → Create Multi-Output Device**.
3. Отметьте два устройства:
   - Ваши основные наушники или динамики (**Master Device**, галка Drift Correction **снята**).
   - **BlackHole 2ch** (галка Drift Correction **включена**).
4. Перейдите в **System Settings → Sound → Output** и выберите созданный **Multi-Output Device**.

## Использование

### 1. Веб-интерфейс (Рекомендуется)

Запуск сервера на локальном адресе `127.0.0.1:8787`:
```bash
python3 ui.py
```
Откройте браузер по адресу: `http://127.0.0.1:8787`

**Возможности веб-интерфейса**:
- **Диагностика (Preflight)**: Автоматическая read-only проверка устройств без нежелательного захвата звука. Кнопка «Проверить уровень» запускает 2-секундный аппаратный тест с измерением пикового уровня в дБ.
- **Управление сессиями**: Просмотр библиотеки, пользовательское название записи, выбор языка транскрипции (`ru`, `en`, `auto`), сортировка по названию, длительности, дате и состоянию, быстрый поиск.
- **Офлайн-диаризация спикеров (v1.1)**:
  - Автономное разделение реплик по говорящим (Спикер 1, Спикер 2, ...) на базе `sherpa-onnx`, `pyannote` и `eres2net`.
  - Запуск как единым пайплайном при записи/импорте (чекбокс «Диаризация речи»), так и отдельной кнопкой в инспекторе завершённой сессии.
  - Потоковое окно 600 с с перекрытием 60 с и автоподбором центроидов дикторов для длинных звонков (вплоть до 8 часов).
  - Поддержка отмены диаризации и сохранения контрольных точек (`diarization_checkpoint.json`).
- **Инспектор транскрипта**: Просмотр распознанного текста с таймкодами и бейджами спикеров, фильтрация по ключевым словам.
- **Экспорт**: Скачивание результатов с разметкой дикторов во всех поддерживаемых форматах: TXT, Markdown, SRT, VTT, JSON.
- **Конспект (Внешний AI Summary)**: Окно генерации конспекта с выбором структуры (Встреча, Лекция, Интервью, Задачи) и строгим информированным подтверждением передачи данных во внешнюю LLM.

### 2. Консольный интерфейс (CLI)

```bash
# Запись системного звука / Zoom (сессия создается автоматически)
python3 -m recorder.cli record --kind zoom

# Запись с микрофона с выбором устройства
python3 -m recorder.cli record --kind mic --list
python3 -m recorder.cli record --kind mic --mic 1

# Тестирование уровня сигнала (3 секунды)
python3 -m recorder.cli record --kind mic --test

# Распознавание последней сессии
python3 -m recorder.cli process

# Распознавание и диаризация сессии по спикерам
python3 -m recorder.cli process <session_id> --diarize --speakers 2

# Импорт и распознавание готового файла с указанием языка
python3 -m recorder.cli process ~/Downloads/lecture.m4a --lang ru
```

Традиционные shell-скрипты (`record.sh`, `record-mic.sh`, `process.sh`) сохранены для обратной совместимости и используют защищенное ядро.

## Конфиденциальность и саммари

1. **Whisper**: Работает локально на вашем компьютере (GPU Metal или CPU). Аудиоданные не покидают устройство.
2. **Внешние LLM**:
   - **Claude CLI**: Поддерживается с принудительной изоляцией инструментов (`--tools ""`). Требует предварительно настроенной переменной `ANTHROPIC_API_KEY` при использовании режима `--bare`.
   - **Codex CLI**: Отключён по соображениям безопасности (песочница read-only оставляет доступ к локальным файлам для prompt-injection).
   - Текст отправляется во внешнюю LLM **только при явной установке чекбокса согласия** пользователем.

## Операционное восстановление при сбоях (Crash Recovery & Guardian)

Пайплайн спроектирован для обеспечения сохранности закрытых аудиофрагментов при программных сбоях и аварийном завершении UI:

1. **Процесс-хранитель (Guardian Process, `recorder.guardian`)**:
   - При старте записи создаётся выделенный процесс-хранитель, получающий открытый файловый дескриптор блокировки ядра (`fcntl.flock`).
   - Родительский процесс передает владение дескриптором без отправки `LOCK_UN` (close-only), благодаря чему блокировка удерживается ядром ОС даже при внезапной гибели родителя (`kill -9`).
   - Хранитель изолирован от дочернего воркера (`stdin=subprocess.DEVNULL`) и контролирует канал ввода UI через неблокирующий опрос `select.select`.
   - При завершении родительского процесса хранитель фиксирует `EOF`, корректно завершает дерево дочерних процессов (с эскалацией `SIGINT` → `SIGTERM` → `SIGKILL`), верифицирует исчезновение группы процессов, индексирует все закрытые аудиосегменты из `journal.csv`, обновляет манифест сессии (`status: ready` или `status: interrupted`) и освобождает блокировку.
2. **Автоматическая выверка при старте (`reconcile_on_startup`)**:
   - При каждом запуске сервера `ui.py` сканирует каталог записей.
   - Если обнаружена сессия со статусом `recording` или `processing`, но соответствующий процесс завершился, статус автоматически переводится в `interrupted` с сохранением всех закрытых файлов.
3. **Повтор и продолжение обработки (Retry & Resume)**:
   - Прерванные или завершившиеся ошибкой сессии закрепляются вверху таблицы записей с кнопкой **«Повторить»**.
   - Нажатие кнопки переводит сессию в состояние `ready` («Ожидает»), после чего оператор может запустить обработку кнопкой **«Распознать»**.
   - Исходные аудиозаписи (`raw/*.wav`) никогда не модифицируются и не удаляются.

> [!WARNING]
> **Границы гарантий восстановления**:
> Проверена сохранность закрытых 120-секундных аудиосегментов и журнала при программных прерываниях (SIGINT, SIGTERM, parent death).
> Реальные аппаратные сбои питания (power-loss), отказ дисковых контроллеров или паника ядра ОС в тестах не проверялись и аппаратно не гарантируются; незакрытый хвост текущего фрагмента при аварийном обесточивании теряется.

## Диагностика и устранение неполадок (Troubleshooting)

### 1. Доступ к микрофону заблокирован в macOS
Если в диагностике отображается статус `Доступ к микрофону заблокирован в macOS`:
- Откройте **Системные настройки → Конфиденциальность и безопасность → Микрофон**.
- Убедитесь, что для приложения Terminal / iTerm / Python включен переключатель доступа.
- Для полного сброса системных разрешений в терминале выполните:
  ```bash
  tccutil reset Microphone
  ```
  После этого перезапустите сервер и подтвердите системный диалог доступа.

### 2. Ошибка блокировки `Operation busy`
Если операция сообщает, что процесс заблокирован:
- Проверьте текущий статус и активные сессии в веб-интерфейсе (`http://127.0.0.1:8787`) или через статус-API:
  ```bash
  curl -s http://127.0.0.1:8787/api/status
  ```
- Для остановки зависшей сессии используйте встроенные элементы управления UI (**«Остановить запись»** или **«Отмена»**) либо отправьте сигнал `SIGINT` процессу-хранителю через консоль.
- Не завершайте сторонние процессы исключительно по сохранённому PID в файле без проверки совпадения токена сессии и имени команды (`is_process_alive_and_ours`). Никогда не удаляйте lock-файлы и исходные аудиоданные вручную при живом процессе.

### 3. В записи Zoom слышна тишина
- Проверьте, что в Zoom в качестве устройства вывода (Speaker) выбран **Multi-Output Device** или системный звук по умолчанию.
- В приложении **Audio MIDI Setup** убедитесь, что в составе Multi-Output Device включен **BlackHole 2ch** и для него установлена галочка **Drift Correction**.

## Разделение области действия (Scope: Реализовано vs NOT VERIFIED)

Для инженерной честности и воспроизводимости архитектура четко разграничивает проверенные программные свойства и непроверенные аппаратные/внешние условия:

| Компонент / Функция | Статус | Доказательство / Границы |
|---|---|---|
| Непрерывный сегментированный захват звука | **Реализовано** | `ffmpeg segment`, нативная частота, `journal.csv` |
| Офлайн-нормализация 44.1/48 кГц → 16 кГц mono | **Реализовано** | Доказано на точных синтетических WAV 44.1k/48k (56000 фреймов / 3.500 с) |
| Изоляция Whisper и предотвращение PIPE deadlock | **Реализовано** | Потоковое вычитывание stderr/stdout в фоновых потоках |
| Раздельный стейджинг GPU/CPU Whisper | **Реализовано** | Изолированные префиксы `gpu_chunk_*` и `cpu_chunk_*` |
| Межпроцессная блокировка с наследованием flock | **Реализовано** | `ProcessLock`, guardian, close-only передача дескриптора |
| Guardian process с неблокирующим циклом | **Реализовано** | `select.select`, `stdin=DEVNULL`, эскалация группы |
| Точное сопоставление токенов процессов (F04) | **Реализовано** | Парсинг argv (`--token <val>`, `--token=<val>`), защита от коллизий префиксов |
| Защита от symlink и hardlink атак | **Реализовано** | `O_NOFOLLOW`, `st_nlink == 1`, проверка путей |
| Web UI по спецификации Apple Design Tokens | **Реализовано** | Канонические CSS-токены, строгие размеры контролов ≥ 44×44 px |
| Поле произвольного названия сессии в Web UI | **Реализовано** | Задается при создании сессии (`manifest.title`); редактирование существующего названия отложено |
| Селектор языка транскрипции в Web UI | **Реализовано** | Варианты `ru`, `en`, `auto` подтверждены в UI; передача проверена на backend |
| Единая библиотека с закреплением исключений | **Реализовано** | Сортировка по severity (`failed` > `interrupted`), каталог ограничен 100 записями с индикатором |
| Доступная клавиатурная навигация меню экспорта | **Реализовано** | ArrowDown/ArrowUp/Home/End/Escape, восстановление фокуса |
| Контроль поколений диагностики (Preflight Generation) | **Реализовано** | Исключение гонок при смене источника или устройства |
| Локальный таймер длительности активной записи | **Реализовано** | Расчет от авторитетного штампа времени, подсказки у Stop/Cancel |
| Саммари через изолированный Claude CLI | **Реализовано** | Флаг `--tools ""`, обязательный информированный opt-in |
| Локальный AI Summary | **Отсутствует** | Локальная LLM не встроена; вывод транскрипта является расшифровкой речи, а не саммари |
| Физический аппаратный захват микрофона/BlackHole | **NOT VERIFIED** | Программный стек проверен; физический тракт зависит от ОС/железа |
| Многочасовая непрерывная запись (≥ 4 ч) | **NOT VERIFIED** | Проверено синтетическими тестами; многочасовой запуск не производился |
| Реальное распознавание физической моделью Whisper | **NOT VERIFIED** | Проверено на моках и синтетических данных; натурные веса модели не тестировались |
| Реальные ответы внешнего Claude API | **NOT VERIFIED** | В тестах использовались заглушки; внешние сетевые запросы заблокированы |

## Протокол ручной 4-часовой приемки физической записи (Manual Verification Protocol)

> [!NOTE]
> Данный протокол является инструкцией для ручной натурной верификации на физическом оборудовании. Автоматизированными тестами он не выполнялся.

1. **Фиксация условий и эталона**:
   - Зафиксировать источник аудио (например, BlackHole 2ch с эталонным аудиогенератором).
   - Определить фактическую нативную частоту дискретизации устройства (через `system_profiler SPAudioDataType` или утилиту **Audio MIDI Setup**).
   - Подготовить непрерывный эталонный аудиоматериал известной длительности (например, 4 часа = 14400.00 с) с точными временными сигналами/метками.
   - Не использовать несинхронизированные системные часы (wall-clock) как точную метрику потери сэмплов из-за естественного температурного дрейфа кварцевых генераторов.
2. **Запуск и проведение записи**:
   - Запустить непрерывную запись через CLI или UI:
     ```bash
     python3 -m recorder.cli record --kind zoom
     ```
   - Зафиксировать начальные показатели памяти и CPU (`ps -o pid,rss,%cpu -p <pid>`).
   - Провести непрерывную запись не менее 4 часов.
   - Штатно остановить запись кнопкой **«Остановить запись»** в UI или нажатием `Ctrl+C` в CLI.
3. **Проверка исходных данных (Raw Data)**:
   - Снять и сохранить контрольные суммы всех файлов в `out/<session_id>/raw/` (`shasum -a 256 raw/*.wav`).
   - Проверить непрерывность журнала `raw/journal.csv`: отсутствие временных разрывов между сегментами (`start_time` следующего сегмента равен `end_time` предыдущего).
   - Измерить точную длительность каждого сегмента как `n_frames / sample_rate` через `ffprobe` / `wave` и вычислить их сумму.
4. **Нормализация и проверка целостности**:
   - Запустить поддерживаемую процедуру нормализации/обработки:
     ```bash
     python3 -m recorder.cli process <session_id> --lang ru
     ```
   - **Только после завершения нормализации** измерить параметры результирующих файлов `normalized/chunk_*.wav`:
     - Формат: строго mono, 16000 Гц, PCM 16-bit (`pcm_s16le`).
     - Измерить точную длительность каждого нормализованного фрагмента как `frames / 16000`.
     - Сверить сумму длительностей нормализованных файлов с суммой длительностей исходных raw файлов с учетом допустимой погрешности ресемплирования/округления (до 1 сэмпла на сегмент).
5. **Оценка аппаратного дрейфа и потерь (Drift / Dropouts)**:
   - Сверить таймкоды распознанных речевых меток/сигналов с эталоном.
   - Критерий приемки: отклонение суммарной длительности от эталона составляет **менее 0.05%** (не более 7.2 секунды за 4 часа записи). Данный порог является критерием приёмки, а не гарантированным свойством оборудования.
6. **Повторная сверка и критерии отказа (Fail Criteria)**:
   - Повторно сверить SHA-256 контрольные суммы файлов `raw/*.wav` с исходными (гарантия неизменности исходников).
   - **Критерии FAIL**:
     - Изменение хеш-сумм файлов `raw/*.wav`.
     - Нарушение монотонности временных меток в `journal.csv`.
     - Ошибки декодирования заголовков RIFF/WAVE в `normalized/`.
     - Расхождение между эталоном и записью > 0.05% при отсутствии аппаратных сбоев.
     - Зависание процессов или неосвобожденная файловая блокировка.
   - При сбое сохранить: архив директории сессии, системный лог `journal.csv`, вывод `system_profiler SPAudioDataType` и логи `ui.py`.
